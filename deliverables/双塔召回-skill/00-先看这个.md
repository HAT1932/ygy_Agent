# 双塔召回 · 穿搭评审 skill —— 交付说明

> 任务理解：用大模型模拟「用户塔 × 衣服塔」。先输入若干套参考穿搭建立"穿衣基因"，
> 之后每输入一件衣服，立刻输出**适不适合 / 分数 / 原因 / 风险 / 建议**。
> 交付目标：把这条链路**固化成一个可复用的 skill**，而不是一次性的对话。

---

## 2. 怎么复现（30 秒）

```powershell
python skill_demo.py --offline            # 离线：规则引擎 + 模板文案，5 个 case 出表
python skill_demo.py --offline --literal  # 对照组：改用"词表精确比对"看差异
python skill_demo.py --online --image <图片路径>   # 接真模型：VLM 解析 → 判断 → 说明
```

## 3. 结论长什么样（离线实测）

```
case           判定      总分     D1    D2    D3    D4    D5
case_y2k       强烈推荐  82.0   15.6  22.0  13.2  17.6  13.6
case_commute   适合      69.0   15.6  16.0  13.2  10.6  13.6
case_clash     不适合    65.2    7.8  13.0  13.2  17.6  13.6
case_banned    不适合    67.0   15.6   7.0  13.2  17.6  13.6
case_formal    适合      69.0   15.6  16.0  13.2  10.6  13.6
```

每次输出固定包含五件事：**判定 → 分数（五维）→ 原因（带证据）→ 风险（不改会怎样）→ 建议（改哪里、能涨几分）**。

## 4. 三个关键设计决策（也是我最想聊的部分）

1. **判断不交给大模型。** LLM 负责"看"（解析单品）和"说"（润色措辞），分数由规则引擎算。
   理由：LLM 每次给的分数都不一样，无法验收、无法回归测试；规则引擎确定性、可追溯、能批量。
2. **风格必须过一层"家族"。** 受控词表只有 25 个词，模型却会说 Y2K / 千禧 / 古早 / 辣妹。
   不做家族归并，这些信号会在匹配时被整段丢掉——实测同一套衣服从 56 分变 74 分，只差这一层。
3. **参考不是越多越好。** 实测 3–5 套同风格主线最强；超过 5 套会摊薄主风格权重（0.60 → 0.15），
   10–20 套容易出现"平均人画像"。所以默认按加权聚合 + 诊断提示，而不是无脑平均。

## 5. 目前还差什么（诚实说明）

- **参考套数**：本次演示用 3 套（已验证链路），设计上支持 3–20 套；**10–20 套真照片的完整跑批还没做**。
- **真实图像**：批量结果是结构化 JSON 输入的（验证判断层）；单张真图的解析路径已实现，
  可现场跑 `--image`，但尚未做 20 张真图的识别准确率统计。
- **审美质量**：评测集是合成的，Spearman 只能证明"链路正确、排序合理"，不能证明"和真人审美一致"。

## 6. 一句话

**输入若干套参考穿搭 + 一件待评衣服；衣服塔结构化 → 用户塔画像 → 规则引擎确定性打分；
输出适不适合 + 分数 + 每条扣分的证据、风险与改法。**
