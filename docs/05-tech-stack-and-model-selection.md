## 0. 结论摘要（TL;DR）

| 决策项 | 结论 | 一句话理由 |
|---|---|---|
| **VLM（图片解析）** | **阿里云百炼 Qwen3.7-Plus** | 唯一「图像 token 预算可调」到 16,384 的主选项（DeepSeek 硬顶 1,024），且同族有开源权重退路 |
| **文本 LLM（解释合成）** | **DeepSeek `deepseek-flash`** | 1 元/百万输入、4 元/百万输出（空闲时段），全市场最低档且中文表达好；任务本身只是「翻译成人话」 |
| **跨模态 Embedding** | **Qwen3-VL-Embedding**（文本 0.7 / 图片 1.8 元/百万 token） | 月成本仅 2.78 元；同价档还有豆包 embedding-vision，可选其一 |
| **向量库** | **PostgreSQL + pgvector**（MVP）；二期 Milvus | 一年 < 3 万向量，pgvector 够用，省一个组件 |
| **后端框架** | **Python 3.12 + FastAPI + Pydantic v2** | AI SDK 生态最全；Pydantic 直接服务「字段缺失率 < 10%」与 §8 契约校验 |
| **队列** | **Celery 5 + Redis** | 重试/超时/幂等/`task_id` 语义最完整，直接落地 §9 `202 + task_id` |
| **对象存储** | **阿里云 OSS**（与百炼同区） | 内网传图给 VLM 免流量费；生命周期规则自动删除满足 R-06 |

### 三档月成本（**真实单价**，1000 次 Report + 100 用户建画像/月）

| 档位 | 组合 | 月成本 | 单 Report |
|---|---|---|---|
| **A 极致省钱**（单厂商） | DeepSeek Flash 解析 + 合成 | **17.30 元** | 1.37 分 |
| **B 推荐** | Qwen3.7-Plus 解析 + DeepSeek Flash 合成 | **25.21 元** | 1.94 分 |
| **C 质量优先** | Qwen3.8-Max 解析 + 合成 | **153.58 元** | 12.38 分 |

> **最关键的一个数字**：A 与 B 只差 **7.91 元/月**。
> 这 7.91 元买到的是：**图像 token 预算从硬顶 1,024 变成可调至 16,384** + **开源权重私有化退路**。
> 在本产品 baseline 明确标注为高风险的 R-01（材质误识别）与 R-06（隐私）上，这是极便宜的保险。**所以 B 是推荐档，而不是最便宜的 A。**

**三条反直觉结论**：

1. **「DeepSeek 只有文本 API」是错的**。`deepseek-flash`（= DeepSeek-V4.1-Flash-1017）官方文档明确标注「图像理解：支持」，1M 上下文、384K 输出、支持 JSON Output / Tool Calls。旧的 `deepseek-v4-flash-vision-exp` 已下线，请求由 V4.1-Flash 承接并按 Flash 价格计费（§3.1）。**单厂商路线（一个 Key 干完解析+合成）在成本上是可行的，只贵在图像细节预算。**
2. **成本大头仍是 image token，但两家已收敛到同一量级**：Qwen 是 32×32 像素/Token，1024×1024 图 = **1,024 token**；DeepSeek 每图**硬顶 1,024 token**。所以厂商间的 image token 差异不再是数量级差异，而是**上限**差异（1,024 vs 可开到 16,384）。
3. **真正被低估的成本陷阱是「思考模式」**。百炼文档写明 `qwen3.8 / qwen3.7 / qwen3.6 / qwen3.5 系列模型` **默认 `enable_thinking = true`**。若不做处理，解析任务会额外产出上千 reasoning token，B 档 VLM 成本从 15.81 元涨到 32.61 元（**+106%**）。这是本文档最值钱的一条工程提醒（§7.5.3）。

## 1. 选型原则与权重

| 权重 | 原则 | 为什么对本产品重要 |
|---|---|---|
| **30%** | 国内可直连（无合规/无代理依赖） | 面向中国大陆 C 端；跨境调用带来延迟、可用性、数据出境合规（R-06）三重风险 |
| **25%** | 结构化输出可靠（JSON Schema 遵循率 / 字段缺失率） | baseline P0-2 要求「字段缺失率 < 10%」，P0-6 规则引擎完全依赖字段齐备；解析不稳 = 规则乱触发 = 分数不可复现 |
| **20%** | 中文服饰术语表现（受控词表命中） | 「法式」「通勤知性」「廓形」「落肩」「缎面」是受控词表，通用模型易给近义词漂移 |
| **15%** | 单价与可替代性 | 见 §7：MVP 量级下单价权重低；但必须有 ≥2 家可切 |
| **10%** | **图像细节预算**（可用 image token 上限，是否可调） | 材质/纹理/小配饰的判别力直接由 image token 预算决定；这是 R-01 的根 |

**一票否决**：不能稳定返回可校验 JSON 的；必须跨境且无境内合规方案的；不支持中国大陆主体的。

### 2.3 image token 折算规则（本次拿到的官方公式）

这是成本模型的地基。v0.1 靠猜，v0.2 有官方依据：

| 厂商 | 官方规则 | 1024×1024 图 | 每图上限 | 可否加钱提高 |
|---|---|---|---|---|
| **阿里百炼 Qwen** | 每 Token 对应 **32×32 像素**；`vl_high_resolution_images=false`（默认）时 `max_pixels` 默认 **2,621,440**、最大 16,777,216；`=true` 时固定策略、`max_pixels` 失效 | **1,024 token** | 默认 **2,560**；high-res **16,384** | **✅ 可调** |
| **DeepSeek** | 图片自动缩放（<544×544 放大，更大缩到约相当于 1300×1300），**每图 token 上限 1,024**；`detail: low` → 512×512 更省 | **≈1,024**（硬顶） | **1,024** | ❌ 不可提高 |
| **火山方舟（向量）** | `min((w×h)/784, 1312)` | ≈1,312（顶格） | 1,312 | 视模型 |
| 智谱 GLM 视觉 | **未查证**（价格页无公式） | — | — | 未查证 |
| Gemini | **未查证** | — | — | 未查证 |

**这张表是本文档的选型分水岭**：两家国内主选在「1024×1024 图」上消耗的 token 几乎相同（1,024），**差别在「能不能花钱买更多细节」**——Qwen 可以（2,560 / 16,384），DeepSeek 硬顶在 1,024。而 baseline R-01 明确把「材质识别不准」列为高风险，材质/纹理恰恰依赖细节 token。

## 3. 多模态理解模型（VLM）选型

用途（baseline P0-2 / P0-5）：单图/多图 → `Garment[]`（颜色/版型/材质/品类/风格标签）+ `Outfit` 层级关系。**全链路最脆弱、最影响可解释性的一环**。

### 3.1 关键核实：DeepSeek 的多模态现状（**v0.1 结论已推翻**）

**v0.1 的判断**：DeepSeek 只有实验性 vision（`-Exp`），只作备选。
**v0.2 核实后的事实**（来源：DeepSeek 官方「模型 & 价格」页 + 「图像理解」文档，2026-10-31 抓取）：

| 核实项 | 结论 |
|---|---|
| 主模型是否支持图像 | **是**。`deepseek-flash`（DeepSeek-V4.1-Flash-1017）官方标注「**图像理解：支持**」；`deepseek-v4-pro` 不支持 |
| 上下文 / 输出 | 1M 上下文 / 最大 384K 输出 —— 远超本产品需求 |
| 结构化能力 | **JSON Output ✅ / Tool Calls ✅ / Responses API ✅ / Anthropic API ✅** |
| 图片接入方式 | 3 种：base64 data URL、外部 http(s) URL、Files API `file_id`（可复用同一图） |
| 支持格式 | JPEG / PNG / GIF / WebP（按内容判断，非扩展名） |
| 单请求图片数 | **最多 600 张**；单图 ≤ 32 MiB（Files API 64 MiB）；请求体 ≤ 48 MiB |
| 图片尺寸 | 单边最长 8,192 px；**≥15 张图时降为 4,096 px** |
| **每图 token 上限** | **1,024**（硬顶，不可提高） |
| `-Exp` 模型现状 | **已下线**，旧名 `deepseek-v4-flash-vision-exp` 仍可调用但由 V4.1-Flash 承接，**按 Flash 价格计费** |
| 并发 | 2,500（远高于本产品量级） |
| 中文服饰术语 / 结构化稳定性 | **无公开评测可引用，未查证** —— 必须自建金标集（§3.3） |

**对架构的影响（3 条）**：

1. **「图片解析必须换厂商」这个前提彻底不成立**。单厂商路线（一个 Key 干完解析+合成）在工程与成本上都是**可行的第一选项**，不再是「备选」。§3.5 会认真比较。

3. **`Files API file_id` 是被低估的成本/延迟优化**：建画像时用户常重复上传同一批参考图，用 `file_id` 复用避免重复上传，同时可配合 DeepSeek 的**上下文缓存（命中输入 0.02 元/百万）**把固定 prompt 前缀成本压到近乎归零。

## 5. 跨模态 Embedding 选型

用途（baseline §7.2）：把 outfit 的图像 + 结构化特征投到同一向量空间，产出 `u`（用户塔）与 `v`（搭配塔）。

**先排除一个误解**：需要的是**跨模态（图文同空间）**嵌入。**纯文本 embedding 绝不能用于图像侧**——智谱 `Embedding-3`、各类 `text-embedding` 都属此类，用了就是假双塔。

### 5.1 API vs 自托管

| 维度 | API | 自托管（SigLIP2 / BGE-VL / Qwen3-VL-8B 视觉塔） |
|---|---|---|
| 运维 | 零 | GPU 常驻 + 加载 + 版本管理 + 健康检查 |
| 边际成本 | 按量（本产品 ≈2.78 元/月，§7） | ≈0，但固定 GPU 成本 |
| 数据位置 | 国内 API ✅ | 完全不出域（最优） |
| 显存（量级估算，**须压测**） | — | SigLIP2-B/16 ≈2–4 GB；so400m ≈4–6 GB；BGE-VL-base ≈3–5 GB；Qwen3-VL-8B ≈18–24 GB(bf16) / 10–12 GB(int8) |
| 维度可裁剪 | 依赖厂商 | 自由（128/256） |
| 换模型代价 | **必须全量重刷向量** | 同上 |

**MVP 选 API。** 理由用数字：MVP 月 embedding 成本 **2.78 元**。常驻一张 GPU 卡的月成本远高于此——**在 2.78 元/月量级下谈自托管，是用几百元固定成本换三元可变成本。**

**二期切自托管的触发条件**（任一满足）：① 月调用 > 10 万次；② 需私有化交付；③ 需微调 embedding（§7.2 已留 `TowerAdapter`）；④ 需端到端控制「图文混拼 + 结构化投影」。

### 5.3 结论与三个必须写进代码的约束

- **MVP 主选：`qwen3-vl-embedding`（0.7/1.8）**，理由：与 VLM 同门（语义先验一致、同 Key 同限流池）、图文双档明码标价。**若想进一步压价，先用 `tongyi-embedding-vision-flash`（0.15/0.15）跑通，质量不够再升级**——embedding 是唯一「升级即重刷库」的组件，所以**先用便宜的定型 schema，再一次性换高质量模型重刷**比反过来便宜。
- **二期**：`SigLIP2`（中文弱，作对照基线）/ `BGE-VL`（中文检索更稳）自托管，或沿用 Qwen3-VL-8B 视觉塔。以金标集 + 召回人工相关性（N=20 组）实测决定。
- **三个硬约束**：
  1. **向量空间版本化**：表名/collection 必须带 `emb_v1_<provider>_<model>_<dim>`。换 embedding = 建新空间 + 全量重刷 + 双写灰度，**绝不混用新旧向量**（混用会产生「能跑但相似度全是噪声」的最难排查 bug）。
  2. **入库前 L2 归一化，检索用 cosine**；§7.2 要的 256 维由 adapter 做「取前 N 维 + 重归一化」，**不要指望模型原生输出 256 维**。
  3. **α/β 混拼参数存配置不存代码**：`concat(α·img_emb, β·struct_proj)` 的 0.6/0.4 只是初值，必须能在线调，并把当次参数写进 `Report.meta`，否则 P0-3 的「两次运行差异 < 5%」无法归因。

### 6.1 数据与存储

### 7.2 成本公式（含峰谷与缓存）

```
C_vlm = M_in_vlm × P_in_vlm + M_out_vlm × P_out_vlm
C_txt = M_in_txt × P_in_txt + M_out_txt × P_out_txt
C_emb = M_txt_emb × P_txt_emb + M_img_emb × P_img_emb
────────────────────────────────────────────
```

DeepSeek 的 `P` 有峰谷：空闲时段 = 表价，高峰 = 表价 **×2**（以**请求完成时间**所在时段计费）。

### 7.5 敏感性分析

#### 7.5.1 第一敏感变量：image token 总量

固定 B 档（qwen3.7-plus 2/8），只改「每套几张图 × 每张多少 token」：

| 场景 | 每次 VLM 输入 | 月 VLM 输入 | C_vlm | 相比基准 |
|---|---|---|---|---|
| 1 图 × 1,024（`detail:low` 级） | 800 + 1,024 = 1,824 | 2.55 M | **9.06 元** | 0.57× |
| **2 图 × 1,024（本文基准）** | **2,848** | **3.99 M** | **15.81 元** | **1.00×** |
| 2 图 × 2,560（Qwen 默认上限 / 高细节） | 800 + 5,120 = 5,920 | 8.29 M | **24.42 元** | 1.54× |
| 3 图 × 2,560 | 800 + 7,680 = 8,480 | 11.87 M | **33.58 元** | 2.12× |
| 2 图 × 16,384（Qwen high-res 极限） | 800 + 32,768 = 33,568 | 46.99 M | **109.82 元** | **6.95×** |

> **结论**：模型之间的单价比差异（3–4 倍）**远小于** image token 策略的差异（6.95 倍）。**先做图片预处理（客户端压到长边 1024、去重、必要时只传 1 张全身 + 1 张细节），再谈选哪家模型。**
> **同时注意**：`max_pixels` 是成本旋钮也是质量旋钮——B 档把细节从 1,024 提到 2,560，月成本 25.21 → **33.82 元（多 8.61 元）**。**用 8.6 元/月买 2.5 倍视觉细节，是本产品最划算的一笔钱之一。**

#### 7.5.2 第二敏感变量：输出 token（单价是输入的 3–4 倍）

B 档下 VLM 输出成本 = 0.98 × 8 = **7.84 元**，占 `C_vlm` 的 **49.6%**；而输出 token 只占总 token 的 19.7%。**高单价的少数 token 才是杠杆。**

| 优化动作 | 输出 token | B 档 VLM 成本 | 省下 |
|---|---|---|---|
| 基准（4 单品完整 JSON） | 700/次 | 15.81 元 | — |
| 裁掉可推导字段（内联 `hue_span`、冗余中文描述） | 400/次 | 12.21 元 | **3.60 元（-22.8%）** |
| 严格 JSON mode（禁解释性文字 + `max_tokens` 收紧） | 350/次 | 11.82 元 | **3.99 元（-25.2%）** |

> **「schema 精简 + 严格 JSON mode」比换更便宜的模型更划算**，且同时改善 P0-2 字段缺失率（双赢）。

#### 7.5.3 第三敏感变量：**思考模式（本次新增，最大的隐形陷阱）**

百炼文档明确：`qwen3.8 / qwen3.7 / qwen3.6 / qwen3.5 系列模型默认 enable_thinking = true`。

| 配置 | 每次解析输出 | 月输出 tokens | B 档 C_vlm | 月合计 |
|---|---|---|---|---|
| **`enable_thinking = false`（正确）** | 700 | 0.98 M | **15.81 元** | **25.21 元** |
| 默认（思考开，假设多出 1,500 reasoning tokens） | 2,200 | 3.08 M | **32.61 元** | **42.01 元** |
| 默认 + 未精简 schema（2,700） | 2,700 | 3.78 M | **38.06 元** | **47.46 元** |

> **一行配置错误 = 成本 +67%（+16.80 元/月）；叠加 schema 未精简 = +88%。**
> 必须写进 code review checklist：**调用百炼 qwen3.x 必须显式 `enable_thinking=false`**（OpenAI SDK 走 `extra_body`）；`thinking_budget` 不要留默认（默认 = 模型最大思维链长度）。

#### 7.5.4 峰谷时段：诚实评估（**不要夸大「成本直接减半」**）

DeepSeek 官方与百炼/方舟的 deepseek 档均采用峰谷价：**高峰 = 北京时间周一至周五 9:00–12:00、14:00–18:00（不含法定节假日）；其余时段（含周末）空闲，价格 = 高峰的一半**，以**请求完成时间**判定。

| 场景 | 可调度性 | B 档节省 |
|---|---|---|
| 用户触发的 Report（1,000 次/月） | ❌ **不可调度**（P95 ≤ 20s，用户点了就要出） | 0 |
| 建画像聚合（100 次/月） | ✅ 可延迟到空闲时段 | ≈ 0.26 元/月 |
| anchors 库嵌建（一次性 1 万条） | ✅ 可调度 | 一次性，略 |
| 金标集批量跑分 / 规则回归 | ✅ 可调度 | 一次性，略 |
| **本量级合计** | — | **≈ 0.3 元/月（几乎为零）** |

> **诚实结论**：在 1,000 次/月量级，**峰谷调度的收益约等于 0** —— 绝大多数调用是用户即时请求，而 DeepSeek 那部分成本本身只有 6.62 元/月。
> **它在什么规模下才有意义**：当用量到 10 万次/月，DeepSeek 部分成本约 662 元/月，若其中 70% 可调度则省 **≈232 元/月**。
> **所以正确的工程建议不是「把线上请求挪到半夜」，而是**：① 把**批量/离线任务**统一走「夜间队列」，显式选择空闲时段提交；② 在 `CostMeter` 里记录每笔调用的**计费时段**，用于事后审计「有没有在高峰跑本该批量跑的任务」。**把峰谷当调度策略，不要当省钱的灵丹妙药。**

| 手段 | 机制 | B 档收益 |

| **DeepSeek 上下文缓存** | 命中输入 **0.02 元/百万**（vs 未命中 1 元）→ 固定 prompt 前缀 800 token 近乎免费 | 1.12 M × (1−0.02) = **省 ≈1.10 元/月**（100× 规模省 110 元/月） |

| 固定基础设施（ECS + RDS + Redis + OSS + Langfuse） | **未查证金额**，量级为**几百元/月** | 本次未抓取云资源价格页。三档共用，与选哪家模型无关 |
| 人力 | 主导项 | — |
| 金标集标注 | 一次性 ~1.5 人日 | 可用免费额度把模型成本做到 0 |

> **这张表是对「性价比」最重要的一次纠正**：模型 API 十几到几十元，基础设施几百元，人力几万元。**「模型省钱」对总成本的影响 <2%。** 本项目的「性价比」应定义为「**每单位质量提升所付的钱**」，而不是「最低单价」。B 档之所以是推荐档，正是因为它用 7.91 元/月买到「细节可调 + 开源退路」，性价比极高。

## 8. 推荐组合（最终结论）

| 层 | 推荐 | 一句话理由 |
|---|---|---|
| **VLM** | **阿里云百炼 Qwen3.7-Plus**（2/8，限时 1.6/6.4） | 唯一图像 token 预算可调至 16,384 的主选项（DeepSeek 硬顶 1,024）+ 同族 8B/32B 开源退路 |

| **后端框架** | **Python 3.12 + FastAPI + Pydantic v2** | AI SDK 生态最全；Pydantic 直接服务字段缺失率与 §8 契约 |
| **队列** | **Celery 5 + Redis** | 重试/超时/幂等/`task_id` 语义最完整，落地 §9 异步契约 |

| **前端** | **Next.js + TS + Tailwind + shadcn/ui** | 多图上传 + SSE 分段进度；官网与应用同仓 |
| **可观测** | **Langfuse 自托管** | prompt 版本 + token 成本 + trace 回放 + 金标集回归四合一 |

**三条必做的实施约束（否则成本/质量都会翻车）**
1. **调用百炼 qwen3.x 必须显式 `enable_thinking=false`**（§7.5.3，不做 = 成本 +67%）。
2. **客户端图片预处理到长边 1,024**，且只传必要的 1–2 张（§7.5.1，决定 2–7 倍成本差）。
3. **解析输出走严格 JSON mode 且 schema 精简到 400 token 以内**（§7.5.2，-25% 成本 + 提升字段缺失率指标）。

| 层 | 二期变化 | 触发条件 |

| 双塔 | 不训练 → 用户反馈对做对比学习 | §7.2 已留 `TowerAdapter` |

## 9. 被否决的候选与理由

| 被否决项 | 否决理由 | 复活条件 |
|---|---|---|
| **OpenAI GPT-5 系 / Google Gemini 系（主链路）** | 中国大陆不可直连；用户真人穿搭图出境违反 R-06 隐私设计前提；跨境延迟不可控。**另：OpenAI 定价页 403，价格未查证，无法做性价比论证** | 仅可作**离线参考标注器**（不接触用户真实图）；产品出海时重评 |
| **把 `deepseek-v4-flash-vision-exp` 当独立备选** | **已下线**，请求由 V4.1-Flash 承接并按 Flash 计费。v0.1 把它当「实验性备选」的判断作废 | ❌ 无（模型已不存在） |
| **纯文本 embedding（智谱 Embedding-3、text-embedding-*、BGE-M3 纯文本等）** | 不满足 §7.2「跨模态图文同空间」硬需求。用了双塔就是假双塔 | ❌ 无（能力性否决） |
| **CLIP 原版** | 英文语料，中文受控词表（「通勤知性」「落肩」）漂移严重；分辨率/长文本弱于 SigLIP2 | ❌ 无 |
| **FAISS 作生产向量库** | 是库不是数据库：无持久化、无并发写、无标量过滤、无删除一致性。R-06 要求可删除 | ❌ 无（可作离线评测工具） |
| **Elasticsearch 做向量库** | 为全文检索付过重集群运维成本；本产品只需「纯向量 + 少量标量过滤」 | 有：若同时需中文全文检索 |
| **Django / Node(NestJS) / Go 作后端** | Django async 弱且重；Node/Go 的 VLM/LLM SDK、JSON Schema 校验、token 工具链显著弱于 Python，等于自建轮子 | 无（团队若已是 Node/Go 需接受自建校验层） |
| **`asyncio.create_task` / `BackgroundTasks` 做队列** | 进程重启即丢任务；无重试/超时/幂等 → 违反 §9 可靠性，且任务丢失 = report 缺失 | ❌ 无 |
| **Kafka 做任务队列** | 为 4 步任务付集群运维；无延迟队列/重试语义需自建 | 有：二期事件量级到百万/日且多消费方 |
| **Drools / 纯 JSONLogic 做规则引擎** | 无法表达 `evidence_fields`/`explain_template`/确定性排序/单维度扣分上限；Drools 还引入 JVM | 部分：JSONLogic 的表达式语义可借鉴进自研求值器 |
| **reasoning / 思考档做解析或合成** | 模板化任务，reasoning tokens 计费但不产出。**百炼 qwen3.x 默认开启思考，不显式关闭成本 +67%（§7.5.3）** | 有：若未来做「跨套搭配的长期风格建议」这类真推理任务 |
| **多模态一体化（同一家全包）作为「唯一方案」不加区分地否决** | 见 §3.5：成本上完全可行（A 档 17.30 元），但默认放弃「细节可调 + 开源退路」；且单家限流/涨价即无备胎 | ✅ **有条件复活（且是推荐演进方向）**：金标集证明 1,024 token 够用 → 直接切 A 档 |
| **把峰谷调度当作核心降本策略** | 用户即时 Report 不可调度，本量级收益 ≈ 0.3 元/月（§7.5.4）。夸大它是错误的工程判断 | 有：10 万次/月以上且批量任务占比高时 |

## 10. 降级与可替换性设计

### 10.1 为什么所有模型调用必须走统一 adapter

1. **本项目的模型层必然要换，且不止一次。** 本次核实就推翻了 v0.1 关于 DeepSeek 的核心判断，并发现 `-Exp` 模型已下线——**这个市场的版本半衰期只有几个月**。把厂商 SDK 铺进业务代码，等于把「换模型」从 1 天变成 2 周。
2. **baseline §8 的 `Report.meta.model_versions` 是硬契约。** 报告必须记录 vlm/llm/embedding 三者版本，才能满足「分数可追溯可反驳」。只有调用被统一收口才可能实现。
3. **比价与影子流量实验的前提。** 想验证「A 档换 B 档省多少、质量掉多少」，必须能双跑并把 token 成本与质量指标对齐。没有 adapter，选型只能靠猜——而 §3.3 已论证「靠猜不可接受」。

### 10.2 必须抽象的接口（**对代码结构的唯一硬要求**）

5 个业务接口 + 3 个横切能力。签名以业务语义命名，**绝不允许出现厂商术语**（不允许 `qwen_image_url`、`ark_endpoint` 这类参数）。

```
┌─ VisionAdapter（图片 → 结构）────────────────────────────────┐
│ parse_outfit(images: ImageRef[], hints: OutfitHints,          │
│              schema: OutfitSchema) -> ParseResult[Outfit]     │
│ parse_garment(image: ImageRef, schema: GarmentSchema)         │
│              -> ParseResult[Garment]                          │
│ probe() -> CapabilityReport                                   │
│     // 必须回报：最大图数、单图 token 上限、可否提高细节预算     │
│     // （这正是 DeepSeek 1,024 vs Qwen 16,384 的差异所在；     │
│     //   probe() 要让上层在运行时知道"本 provider 能不能满足     │
│     //   本单的品质要求"）                                      │
└───────────────────────────────────────────────────────────────┘

┌─ TextAdapter（结构 → 人话）──────────────────────────────────┐
│ explain(ctx: ReportContext, style: ExplainStyle,              │
│         constraints: FactConstraint) -> Explanation           │
│ aggregate_profile(samples: GarmentSample[]) -> ProfileDraft   │
│ probe() -> CapabilityReport                                   │
└───────────────────────────────────────────────────────────────┘

┌─ EmbeddingAdapter（图/文 → 向量）─────────────────────────────┐
│ embed_images(images: ImageRef[], space: VectorSpace) -> Vec[] │
│ embed_texts(texts: str[], space: VectorSpace) -> Vec[]        │
│ embed_mixed(items: MixedItem[], space: VectorSpace) -> Vec[]  │
│ space_info() -> VectorSpaceMeta  // 维度/归一化/可否裁剪/最大长度│
└───────────────────────────────────────────────────────────────┘

┌─ 横切（三个，缺一不可）───────────────────────────────────────┐
│ CostMeter.record(call: ModelCall) -> None                     │
│     // tokens_in / tokens_out / cached_tokens / thinking_tokens│
│     // / unit_price / billing_window(peak|idle) / est_cost     │
│     // ← §7.5.3 与 §7.5.4 的审计都依赖这两个字段               │
│ RateLimiter.acquire(provider, est_tokens) -> Token             │
│ RetryPolicy.run(fn, classify_error) -> Result                  │
│     // 区分可重试(429/5xx/超时) 与不可重试(400/内容拒绝)，      │
│     // 且必须幂等重试（同 task_id 不重复计费）                  │
└───────────────────────────────────────────────────────────────┘
```

**额外两条数据契约**
- `ParseResult` 必须带 `warnings: ParseWarning[]` 与 `confidence: float` —— R-01 要求「材质不确定时规则降级为 soft 或跳过并记 `parse_warnings`」，**置信度是规则引擎的输入，不是可选项**。
- `ModelCall` 必须记 `billing_window` 与 `thinking_tokens` —— 否则无法审计「是否误开思考模式」「是否在高峰跑批量任务」，这两个都是本次实测发现的真实成本漏洞。

### 10.3 切换成本如何控制在「天」级（6 条机制）

| # | 机制 | 作用 |
|---|---|---|
| 1 | **业务层禁止 import 厂商 SDK**（CI lint：`providers/` 外出现厂商包名即失败） | 结构上保证可替换 |
| 2 | **provider-neutral JSON Schema**：schema 我们自己定，adapter 负责把厂商输出规整进来 | 各厂商 tool_call / JSON mode 差异关在 adapter 内 |
| 3 | **金标集作为切换门禁**：新实现必须跑 `evals/vision_golden`，不劣于现网才允许切 | 用数据而非信心做决策（§3.3） |
| 4 | **影子流量双跑**：新实现处理 5% 流量（不返回用户，只落库比对），比 token 成本 + 字段差异率 + 人工抽检 | 切换前先拿到「质量差多少/省多少钱」的实数 |
| 5 | **向量空间版本化 + 双写**：`emb_v1_*` → `emb_v2_*` 全量重刷期间双写，灰度切读 | 换 embedding 不停机（最容易翻车的一步） |
| 6 | **prompt 与模型解耦**：prompt 按 `capability`（`vision.parse_outfit.v1`）索引而非 model；每模型可有覆盖层 | 换模型不必重写 prompt，并保留跨模型对比能力 |

### 10.4 降级矩阵（具体路径，含本次核实到的「同模型多供应商」）

| 故障场景 | 一级降级 | 二级降级 | 三级兜底（保证不断服） |
|---|---|---|---|
| **DeepSeek 官方限流/故障** | 切**阿里百炼** `deepseek-v4.1-flash`（1/4 空闲，同价） | 切**火山方舟** `deepseek-v4-1-flash`（1/4 空闲）或「经济版」（0.8/3.2） | 切 qwen3.8-flash 合成；最后模板化生成 |
| **Qwen（百炼）解析故障** | 切 GLM-5V-Turbo / GLM-4.6V（智谱，另一家云） | 切 deepseek-flash 解析（接受细节降级，改 A 档） | **规则引擎降级运行**：颜色走客户端色卡聚类（R-01 已预设），材质/版型置 `unknown` 并写 `parse_warnings`，D5 权重下调，report 标注「解析受限、置信度降低」 |
| **百炼整体涨价 >50%** | 解析切智谱 GLM-4.6V（1/3，更便宜） | 切 qwen3.8-flash（0.8/2.7） | 同上 |
| **解析供应商断供** | 自托管 Qwen3-VL-32B（同族开源权重） | 自托管 GLM-4.5V（已开源） | 同上 |
| **文本 LLM 不可用** | 切 qwen3.8-flash 或 GLM-5.3-Flash | — | **纯模板化生成**：`explain_template` 已存在每条规则（§6.1），可无 LLM 直接拼装 → **LLM 不是必需项，只是「润色器」** |
| **Embedding API 不可用** | 切 doubao-embedding-vision（同价 0.7/1.8，另一家云） | 切 tongyi-embedding-vision-flash（0.15/0.15） | **结构化特征单塔**（`β=1, α=0`）降级召回；丢弃 `cosine(u,v)`，D2 改用标签分布 JS 散度 |
| **向量库不可用** | pgvector 主从切换 | 内存暴力检索（< 3 万条可接受） | `anchors: []`，报告不展示锚点 |
| **队列不可用** | Report 改同步生成（P95 会超 20s 但可用） | — | 排队 + 前端提示预计等待 |

> **本次核实带来的一条重要修正**：**「避免单点」不必靠异构模型**。`deepseek-v4.1-flash` 在 **DeepSeek 官方 / 阿里百炼 / 火山方舟** 三家都有，价格同档（1/4 空闲）——**同模型多供应商**即可实现冗余，且不用改 prompt、不用改 schema。**异构的价值因此回归到「能力互补」而非「可用性冗余」。**
>
> **为什么文本 LLM 的三级兜底是「纯模板化」**：baseline §4 已规定 LLM 不打分、只解释，分数与规则命中全由确定性代码产出。所以 LLM 挂了产品**降级而不失效**。
> **→ 反写回 03 号文档的建议**：`explain_template` 必须是**完整可独立成句**的模板，而不是「给 LLM 的提示片段」。这条兜底只有模板完整时才成立。

## 11. 哪些不要自己做（直接买 / 直接用开源）

**判断标准**：这件事是否构成 baseline 定义的护城河（规则资产 + 可解释性 + 风格度量空间）？不构成 → 一律不自研。

| 不要自己做 | 用什么 | 理由 |
|---|---|---|
| 多模态基础模型 / 服饰检测器 | 买 API（Qwen3.7-Plus / deepseek-flash / GLM-4.6V） | §2.2 明确「不训练」。自训 detector 需 10 万级标注 + 数月，且不如通用 VLM |
| 跨模态 embedding 模型 | API（qwen3-vl-embedding 0.7/1.8）或开源（SigLIP2/BGE-VL） | 训练跨模态对齐需亿级图文对；§7.2 已定「用预训练，不训网络」 |
| 向量检索（ANN 索引） | pgvector / Milvus | 自研 HNSW/IVF 是本项目最典型的自研陷阱：无收益、必翻车 |
| 任务队列 / 重试 / 调度 | Celery + Redis | 极其成熟；自研的幂等/退避/超时语义必然有 bug，而 bug 表现为「report 丢失」 |
| 对象存储 / CDN / 图片处理 | OSS（含压缩、裁剪、格式转换） | 图片预处理直接用 OSS 图片处理参数，**直接决定 §7.5.1 的 image token 成本** |
| 可观测 / prompt 版本 / 成本追踪 | Langfuse（开源自托管） | §9 已否决自研；本次发现的「思考模式漏洞」「峰谷审计」都需要这类工具才能持续监控 |
| LLM 输出的 JSON 校验 | Pydantic v2 + instructor 类库 | 自研 schema 校验等于重写 pydantic |
| 鉴权 / 短信 / 支付 / 实名 | 云服务（阿里云） | 与价值无关；国内合规要求高 |
| **内容安全审核**（用户上传图） | 阿里云内容安全（绿网） | **法规强制项**，自研不可能合规；UGC 图片必须过审 |
| PDF / 报告导出渲染 | HTML → PDF（托管渲染服务） | 自研排版引擎是纯浪费 |
| 前端组件库 / 设计系统 | shadcn/ui + Tailwind | UI 复杂度不高，自研无收益 |

**反过来，这两件必须自己做**（否则失去护城河）：

| 必须自研 | 为什么 |
|---|---|
| **规则 DSL + 求值器 + 规则资产（50 → 1000 条）** | §6.4 明写「规则资产的工程化程度才是护城河」。第三方引擎承载不了 `evidence_fields`/`explain_template`/确定性排序/维度扣分上限 |
| **风格度量空间的定义与调参**（α/β、维度裁剪、画像聚合权重、**image token 预算分配**） | 这是「适合**你**」的实现处（§5.1 D2 权重最高），是产品灵魂，不能外包。**注意：本次核实后，「image token 预算怎么分配到颜色/材质/场合」已成为这个空间的一部分——它是产品参数，不是模型参数。** |
