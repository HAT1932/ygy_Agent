# 09 · 已获授权后的逆向补充清单

> 背景：作者已书面授权逆向。本文回答「授权之后，**哪些事从不能做变成高价值**」。
> 前置结论见 [07-rea-feasibility](./07-rea-feasibility.md)：授权改变的是**法律风险**，不改变**技术产出**——评分逻辑仍在服务端。

版本：v0.1 ｜ 日期：2026-10-31

---

## 0. 一句话

> **授权最值钱的用法不是"多抄代码"，而是换三样逆向永远拿不到的东西：行为实验数据、失败样本、真实业务指标。**

拿到 prompt 只让你知道"别人怎么写的字"；拿到这三样，你才知道"这个维度该给几分才准"——而后者才是真正的差距。

---

## 1. 优先级重排：授权后该做什么

| 优先级 | 动作 | 为什么比逆向更值 | 成本 |
|---|---|---|---|
| **P0** | **直接向作者索取资产**（清单见 §2） | 作者手里有的，比你能逆出来的多一个数量级；且是"合法且免费"的 | 一次沟通 |
| **P0** | **黑盒行为探针**（§3） | 唯一能反解出**权重与阈值**的方法；静态逆向对此完全无能为力 | 1–2 天 |
| **P1** | **索取失败样本库**（§2.5） | 直接构成你的评测集，省掉几周标注；且是竞品踩过的坑 | 一次沟通 |
| **P1** | **索取业务指标**（§2.6） | 校准我们 PRD 里的 H2≥40%、H1≥50% 这些门槛是否有现实依据 | 一次沟通 |
| **P2** | 静态逆向（APK/bundle） | 只剩"实现细节"，而我们不改写别人的代码，收益很低 | 3–5 天 |
| **P3** | 复制 UI/文案 | ❌ 不要做（见 §5） | — |

**判断依据**：你需要的是**「这个维度该给几分」的标定数据**，不是**「别人怎么写这段 prompt」的文本**。前者决定产品好不好用，后者只决定看起来像不像。

## 2. 直接索取清单（拿这张表去问作者）

按"对方持有的可能性 × 对我们的价值"排序。带 ★ 的是**即使授权也很难拿到、但一旦拿到价值极大**的。

| # | 索要物 | 为什么值钱 | 对方持有的可能性 |
|---|---|---|---|
| 2.1 | **评分 rubric 全文**（维度定义 + 每档分值的判定标准） | 我们 docs/03 的 D1–D5 有了外部对照，可校准权重 | 高 |
| 2.2 | **完整的 prompt / system prompt** | 学结构与措辞纪律（如"不许默认夸我"），但只学模式不搬文本 | 高 |
| 2.3 | **规则/阈值表**（如"色相跨度 > 120° 判冲突"具体阈值） | 直接决定我们的规则是不是"拍脑袋定的" | 中 |
| 2.4 | **风格词表 / taxonomy**（如 12 色季 × 8 体型 × 6 风格） | 规则引擎最好的外部知识源；也告诉你哪些维度是有共识的 | 中 |
| **2.5** ★ | **被用户投诉 / 判定出错的样本集**（附人工最终结论） | **直接构成金标评测集**；这是逆向 100% 拿不到的东西 | 低（但值得争取） |
| **2.6** ★ | **业务指标**：DAU、7 日留存、付费转化率、建议采纳率、单份报告成本 | 校准我们 PRD 的门槛；也验证"打分品类没量"这个判断 | 低 |
| 2.7 | **他们的 VLM 提示词与解析字段 schema** | 直接对照我们的 Garment 字段是否缺字段 | 中 |
| 2.8 | **他们踩过的坑清单**（哪些规则误触发率高、哪些场景模型识别差） | 让我们少走弯路，等于白拿几周调试时间 | 中 |
| 2.9 | 是否有内部金标集/标注协议 | 对照 docs/08 的标注协议 | 低 |
| 2.10 | 是否允许我们**引用其结论**（署名方式） | 便于对外沟通"我们对标了谁" | 高 |

> **沟通话术建议**：不要只说"想学习"。明确说明"我们做的是**个人画像驱动**的评审，与你们**通用审美打分**不构成直接竞争"（这一条已由 [06-market-scan](./06-market-scan.md) §2 的竞品分析支撑），并主动提出**互惠**（如分享我们的规则 DSL 设计、评测协议）。

## 3. 黑盒行为探针：反解评分函数的正确做法

这是授权后**技术含量最高、也最被低估**的一件事。核心思想：**把对方当成一个可以查询的黑盒函数，用实验设计反解它。**

### 3.1 为什么这比拿 prompt 有用

| | 拿 prompt | 行为探针 |
|---|---|---|
| 产出 | 一段文字 | **权重 + 阈值 + 边界行为** |
| 可直接用吗 | 只能参考措辞 | 可直接校准我们的 D1–D5 权重与规则阈值 |
| 覆盖 | 只覆盖"设计意图" | 覆盖"实际实现（可能与意图不符）" |

> 真实产品里，**prompt 写的和实际表现经常不一致**（模型不听话、后处理覆盖、规则兜底）。探针打的是"实际表现"，这才是用户感知到的。

### 3.2 实验设计（正交单变量）

以「5 维固定满分」型产品为例（如穿搭日记：协调3/时尚2/场景2/细节2/辨识度1，满分 10）：

**目标**：估计每个维度对总分的贡献函数 `score = Σ w_d · f_d(x) + b`，以及触发扣分的阈值。

**做法**：
1. **基线组**：一套"干净"的搭配（中性色、合身、场合中性、无配饰），重复提 3 次 → 确认输出稳定性（若三次不一致，说明有随机性，必须先量化方差）。
2. **单变量组**：固定其余所有条件，只改一个维度：
   - 颜色组：只改色相组合（同色系 → 邻近色 → 互补色 → 三色以上），5 档
   - 版型组：只改松紧/长短（上紧下紧 → 上松下紧 → 上宽下宽），4 档
   - 场合组：同一套衣服只改声明的场合（通勤/约会/运动/正式），4 档 ← **这一组最能暴露"场景权重"**
   - 细节组：只增减配饰（无 → 1 件 → 3 件），3 档
   - 风格组：只改风格标签一致性，3 档
3. **交互组**：两两组合（如"撞色 × 正式场合"），4–6 组 → 检测是否有 veto/否决逻辑
4. 总计约 **25–30 次提交**，即可拟合出权重与阈值。

### 3.3 从结果里能读出什么

| 观察 | 推论 | 对我们的动作 |
|---|---|---|
| 场合组分数差异大 | 场合适配权重高于宣传值 | 上调我们的 D4 权重（当前 20） |
| 撞色组直接掉到最低档、其他维度也不动 | 存在硬规则 veto | 印证我们 hard rule 设计的必要性 |
| 三次基线重复不一致（如 7/8/6） | 对方**没有确定性打分** | **这是我们的核心优势**：我们的分数可复现（INV-1），可直接作为卖点 |
| 增减配饰几乎不影响分数 | 细节维度是摆设 | 我们的 D5 权重（15）可能应下调，或规则要更具体 |
| 改场合分数完全不动 | 对方"场景适配度"名不副实 | 可写进对标分析的差异点 |

> **最后两行是重点**：探针的最大价值往往不是"学它对的地方"，而是**发现它宣传与实际不符的地方**——那就是你的切入点。

### 3.4 纪律要求

- 每次提交保存原始请求/响应（时间、输入、输出、模型版本）→ 存成 `eval/probe/` 下的 JSONL
- 同一输入至少重复 2 次，先量化随机性再谈差异
- 不使用自动化高频刷接口（尊重对方服务，也避免触发风控）
- 探针样本**不要含真人可识别照片**（用示意/平铺图或对方同意的素材）

## 4. 授权后 taxonomy 的正确用法

Style DNA 的 `12 色季 × 8 体型 × 6 风格类型` 是规则引擎最好的外部知识源。授权后：

| 可以做 | 不可以做 |
|---|---|
| 把它当**知识地图**，检查我们的风格词表是否覆盖完整 | ❌ 直接把他们的分类体系作为我们的产品体系（即使授权，也可能只是"允许研究"而非"允许商用"） |
| 用它对照我们规则库的**维度覆盖漏洞** | ❌ 复制他们的描述文案与命名（著作权独立于研究授权） |
| 引用其**方法论**（如"按色彩季型缩配色候选"）并自己实现 | ❌ 声称是我们的原创 |

> **一句话**：授权通常覆盖"研究/学习"，不自动覆盖"商用复制"。**要看授权书原文的范围与期限**，别用口头授权当商用许可。

## 5. 即使有授权也绝对不要做的三件事

| # | 禁区 | 为什么授权也救不了 |
|---|---|---|
| 1 | **带走对方用户的数据/照片** | 那些数据的主体是**用户**，不是作者。作者无权授权第三方用户的个人数据（PIPL/GDPR 下无效） |
| 2 | **复制 UI 素材、文案、图标、品牌元素** | 著作权/商标权属于各自权利人；"允许你逆向"不等于"允许你复制表达" |
| 3 | **把对方 prompt 逐字放进我们的商用产品** | 授权范围若只写"研究/学习"，商用即越界；且会带入对方的商业导流内容（Modebase 的 prompt 里就有强制广告块） |

**建议动作**：把作者的授权**书面化并存档**（邮件/聊天记录截图 + 日期 + 授权范围原文），在 `docs/` 里留一份 `licenses/` 记录。这既是合规要求，也是将来对外解释"我们对标方式合法"的证据。

## 6. 给我们的最终建议

1. **先发一次索取清单（§2）**，重点争取 **2.5 失败样本** 与 **2.6 业务指标**——这两项逆向拿不到，且直接决定我们的评测集与门槛是否靠谱。
2. **再跑一次行为探针（§3）**，用 25–30 次提交反解权重与阈值，回填到 docs/03 的 D1–D5 权重与规则 delta。
3. **静态逆向降级为 P2**：只在需要"实现细节"时做，不要投入主力。
4. **把"确定性打分"做成卖点**：如果探针发现对方分数不可复现，这直接印证我们 INV-1（同输入同输出）的产品价值——这是可以写进 B 端材料的一句话。
